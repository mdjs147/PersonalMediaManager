# PMM stage-only delivery

BA-001 is strict-card-first. Fetch/read back the exact published scope and adaptation plan on the authorized stage before any implementation. Use the dedicated branch based on that publication and a clean, owned worktree. Never silently expand a card; republish changed scope first.

The current default branch remains main; the delivery baseline is the independent dot stage. They are different facts. Preflight checks actual fetch/push URLs, live default/stage refs, plan ancestry, frozen card blobs, task branch and scope. Runtime probes run rather than merely checking tool names.

First-write and recovery invoke project preflight plus baseline context validation. Pending state permits only the published adoption repair scope. The business-write path always fails in governance-only phase. Commit and push hooks call the project gate; hooks can be bypassed and are not remote security controls.

Freeze implementation before collecting control evidence and independent context review. Commit adoption/configuration/control evidence with the candidate. Then produce test/review/delivery sidecars bound to that exact candidate/tree/base/diff. An author cannot provide their own independent approval. Governed Markdown is reviewed as behavior, not exempted as prose.

Before a Git connector or CLI integration/push, run git-target with the exact action/target, then deliver with genuine sidecars. A precheck does not itself perform or authorize a broader operation. Only fast-forward the approved stage after acceptance; non-fast-forward or concurrently changed remote stops the operation. Read back the exact published SHA and check its CI. No main, release, deployment, force push, security-setting changes or real account access under BA-001.

Prefer Git object identity and exact path scope over duplicate hash ledgers. Keep pending, failed, skipped and unexecuted evidence distinct. Synthetic fixture success and upstream CI do not prove PMM product behavior.
