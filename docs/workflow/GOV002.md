## Required design

- Separate publication, activation, first write, recovery, commit, review and stage delivery. Each operation has explicit task, purpose, actual actor/execution, branch/worktree and candidate/base/target parameters
- Resolve scope and actor from immutable already-published task definitions; candidate edits cannot expand their own permissions. A generic new plan publication reads the trusted previous-stage policy, allows only exact additive plan files, and requires independent review bound to candidate/tree/expected old target
- Planned cards do not become active by existence. Activation binds the published card, predecessor acceptance, phase/purpose, applicability/context and distinct reviewer; actor reassignment uses an explicit independently reviewed activation rather than impersonating the old actor
- Exercise at least two distinct tasks and real actor/worktree changes through the normal path, including publication/readback, activation, first-write, resume, verification/review and delivery. GOV002 proves this in isolated fixture repositories using distinct actual reviewer/author executions and worktrees; fixture remote observations are labelled synthetic. The real DEV001 remote lifecycle begins only after GOV002 is accepted, avoiding a circular dependency. Synthetic fixtures are labelled and cannot claim remote/product acceptance
- Every successor starts fresh current controls/context verification. Preserve nine generic objectives, mandatory navigation, pinned source assets and same-source drift checks. Environment/phase/target changes invalidate the relevant approval
- Business remains false for GOV002 and DEV001. Unknown phase, purpose, undeclared task, missing applicability or failed readiness rejects. A future business phase needs a separately authorized published card and new implementation of its required checks; this card does not authorize that phase
- Local hooks, instructions and actor declarations are bypassable and not authentication. The project gate validates declarations and Git evidence; independent review and live readback remain real separate work
- Git connector updates must use exact candidate, current expected old, correct origin and stage, fast-forward ancestry and force:false. GitHub update_ref has no CAS; recheck immediately before write and after write, report race limitations and stop on drift
