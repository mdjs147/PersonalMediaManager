## Scope

Implement a fresh minimal loop: manually create a local Movie/Series → save explicit season/episode and coverage members in a new isolated SQLite database → consistently read/list them through independent connections → preview manual numbering entirely in memory. Works need no TMDB identity; same-title works have distinct WorkIds. This implements only offline core subsets of works.create_local/get/list, works.coverage_read/save and recognition.numbering_preview. It does not accept their complete UI/HTTP/MCP capabilities or all 219 business capabilities. No old implementation, tests or completion counts are adopted; registered old contracts are read-only design inputs.

The [frozen contract](../requirements/dev002/contracts.en.md) governs domain behavior: one explicit manual numbering system per Series; nonnegative Int32 season numbers, with exact decimal text only for episode ordinals; preserve raw spelling and canonical keys. Coverage is a nonempty explicit ordered member set. Never fill gaps, expand endpoint ranges, infer cumulative numbering, special episodes, resource presence or completion denominators. CreateWork and ReplaceManualCatalog carry nonempty RequestIds; the latter requires ExpectedRevision. Reference constraints, CAS, state changes and the successful receipt belong to one transaction.

Persistence exposes only CreateFresh(), which creates its own unique new temporary database. It accepts no path or connection string and must not open old/real media databases or backups. Each session uses an independent real connection; one read transaction keeps a snapshot's revision and children consistent. Preview binds the supplied snapshot's Work/NumberingSystem/Revision and returns only explicit mappings and issues. It does not consult a store or change the snapshot, database, receipt or revision, does not claim the snapshot is still live-current, and provides no adoption endpoint.
