# 完成来源与历史证据

`GET /dashboard/stats` 的可选新增字段 `completionProvenance` 只统计当前状态为 Completed 的保留记录。统计类别互斥，总和等于 `completed`：

- `confirmed`：最新完成步骤含 `confirm=true`，证明经审核确认完成，不证明改过 TMDB ID
- `manualArchive`：最新完成步骤含 `manual=true`，证明走手动归档
- `automaticPipeline`：最新完成步骤含 `provenanceVersion=1` 与 `completionRoute=AutomaticPipeline`，仅证明最后自动管线完成，不证明全程无人介入，也不证明匹配正确
- `unknown`：没有最新完成步骤、无支持的完成证据、数据损坏或相互冲突；不能用 Rule/Ai/Hybrid 解析来源补猜

步骤按 StartedAt、Id 排序，只用最新完成步骤决定类别。Ignored/Failed/Skipped 等当前非完成记录不进入上述分母。`everReviewed`、`everConfirmed`、`explicitCorrection`、`forcedAnchor`、`folderReuse`、`automaticRetry` 是可重叠的保留历史标记，不是另一组互斥类别，也不是全生命周期保证。

ParseSource.Manual 表示强制锚定；Hybrid 可能表示文件夹复用，不能直接认作纯 AI 或无人干预。旧 source=manual/reuse 只在解析与匹配阶段作为锚定/复用证据。队列 Manual 来源不证明人工重试；自动重试证据取 sweeper 的 autoRetry 标记。文件夹复用的上游人工来源目前不可完整追溯。

确认/改绑现在在同一次数据库保存中追加版本化操作证据，包含旧/新 TMDB ID、类型、季集与分类，以及单独的变更标志。首次绑定、确认已有绑定、替换已有 ID/类型/季集值、缺字段补全分别记录。自动补季与电影季集清理单独标记，不计作人工季集更正。操作已应用不等于后续归档成功。调用者身份无法可靠确定时保留 actorCategory=Unknown 与入口 ReviewApi/HistoryApi；自动管线 actorCategory=System 只指执行器。未保存凭据或无关身份信息。

历史详情新增 currentBlockingReason，仅 AwaitingReview/Failed 返回当前原因；historicalReviewReason/historicalErrorMessage 单独保留历史。兼容字段 errorMessage 不移除，不清空数据库证据。

## 限制与存储

复用既有 Process_Step.Detail JSON，不改表结构，不需要迁移。旧 API 字段继续兼容。现有重新处理流程仍可能删除旧记录及步骤，因此“没有标记”永远不能证明全程自动；本次不重写尝试生命周期。统计每次读取当前已完成记录及其步骤，数据量明显增大时应再做受控分页/缓存优化，不能以丢证据换速度。当前统计也不是跨删除操作的永久审计账本。

合成测试覆盖：最新标记与同时间戳顺序、待审后自动重试、确认未改 ID、显式改 ID、手动归档、非完成排除、缺失/损坏步骤 Unknown、当前原因与历史原因分离。测试只用临时 SQLite 和桩依赖，不使用用户媒体数据库或外部供应商。
