# 规则引擎的证据与执行边界

本轮随产品 0.4.0 交付；产品版本仍只维护根 `Directory.Build.props` 的 `PmmProductVersion`。编号与诊断字段是兼容追加，不新增数据库表或迁移，也不重写用户保存的规则。

## 语法事实和作品身份

显式 `S02E03` 可以证明文件声称第二季第三集，不能证明对应某个 TMDB 身份或官方集序。日期、卷号、绝对号、篇章、版本和放送分期分别保存候选，缺少目录映射时不转成季内集号。字段冲突保留优先值与各层原文并转审核；置信度不是身份核验。

文件证据优先，祖先段仍全部检查。文件小数集或非法列表被拒绝后，不允许父目录整数补回。父目录范围通常描述整包，不把范围末端赋给当前单个文件。

新建默认规则使用 `airDate`、`volume`、`absolute` 等命名空间；已有历史规则即使仍把这些编号捕获为 `episode`，也经过共享语义守门。用户明确的候选捕获保留其语义及来源，不能在后续被裸数字启发式重新解释。

待核实标题查询在检索及最终身份写入前都检查候选状态，AI 换名或文件夹缓存不能把候选关系洗成已确认。文件内未映射的编号在身份写入前转审核；纯父目录包范围不能让电影凭空缺集号。TV 版次标记不靠目录集数范围证明集序，只有真实剧集组映射成功（范围起止都成立）才解除对应缺口；只指定 TMDB ID 或季号仍不足以自动归档该版次。

## 可回放诊断

`NumberingEvidence` 保存 `Kind`、`State`、`Field`、来源及 UTF-16 区间。`Token` 必须等于对应原文区间。`Accepted` 表示局部语法被接受；`Candidate`、`Rejected`、`Conflict` 不可当成官方目录已核验。`RuleKey` 的内置值定位语义家族，用户值定位规则与命名捕获；它不是外部作品ID。

`NamingEvidence.TitleCandidateDecisions` 记录标题候选的保留或淘汰原因，包括描述词、未核验篇章、找不到原文区间等。原始输入和主标题证据不因候选被淘汰而删除。

`Diagnostics` 记录规则数量、匹配尝试、缓存命中、耗时、执行状态和有界事件。用户规则使用规则ID及模式SHA-256定位，不将完整路径或原始模式正文写入该轨迹。128条事件上限到达后，故障原因仍单独保留，不能把截断误当无故障。通用诊断层负责对内容脱敏、截断及落盘。

## 执行约束

正则使用文化无关、忽略大小写选项，预览与执行复用同一缓存和选项。预览仅测试传入样本的正则捕获，不运行标题补充、语义裁决和TMDB流程。

编译正则缓存最多512项，模式执行上限8192字符；保存规则仍遵循原有1000字符上限。每次匹配输入上限32768 UTF-16字符，批量匹配最多256项，单次正则超时500毫秒。规则计算采用2000毫秒总预算并逐操作检查取消；这是检查点预算，正在运行的一次匹配及收尾会产生额外开销，不是硬实时2秒保证。

损坏规则、超时、超预算或输入截断会标记 `incomplete`，压低置信度并形成审核冲突。此时不输出可执行的当前集或结束集，防止不完整语义检查被后续映射误用。调用方取消继续传播取消异常。

## 验证口径

验证覆盖无用户规则、当前默认规则、保留历史规则三种配置。合成正反例验证语义；真实输入的无标签差异扫描仅报告字段变化，不能称作准确率。人工强制绑定的记录不计为新自动识别正确，历史观察一致也不等于官方目录正确。未验证的目录映射保持候选或待确认。
