# AI 有界批量解析

## 默认和启用

外部 AI 批大小与本地模型批大小均默认 **1**，继续使用原单条提示词、请求与校验流程。本地模型模式仍默认关闭。升级不会自动启用模型或增大已有运行时上下文，也不改变提供商启用状态。

管理页面的两个批量设置入口共享独立 KV 配置，通过 GET/PUT /api/settings/ai-batch 读写。外部范围 1–128，本地范围 1–2；大于 1 是用户显式启用的实验性行为。无需数据库迁移。设置损坏时退回单条默认。Worker 读取设置遇到瞬时故障或非停机取消时保留已出队首项，以安全单条继续；真正停机取消仍立即退出。

批量只减少兼容请求提交数，不能据此推断更快或更准确。小模型的闭集格式正确也不等于作品身份正确；原有候选、人工确认、年份/类型/季集核验继续执行。独立合成样例实验不构成产品对真实媒体的精度背书，严禁擅自用私有媒体样本压测。

## 真实入口与串行边界

TaskProcessorWorker 从现有容量 1024、满时等待的队列有界取项。每项独立作用域与数据库上下文，顺序运行到真正需要 AI 的暂停点。规则已经解决的项不会为了凑批调用 AI。

AiBatchPipeline 汇集兼容推理请求，完成后逐项放行；数据库状态写入、文件归档、清理不会同时执行。取队列与等待就绪项的收集窗口各自受 maxWaitMilliseconds 约束。较慢的下一项准备不会无限拖延已就绪请求发送；推理完成不立即唤醒所有业务续行。

暂停点不在 SQLite 显式事务、文件流、归档租约或共享互斥锁内。每项取消信号单独保留，所有项均取消才取消共享传输。单项取消不会把兄弟项结果配给它。停机逐项释放暂停源并等待作用域清理。归档前再检查同哈希、已完成且目标仍存在的有效副本，处理同批准备造成的去重时间窗口。

## 协议与资源边界

外部按提供商 ID、协议、完整端点配置、模型、提示词、任务类型、schema 和输出档位分组。内存分组键不含每项正文，否则会退化为永远单条；密钥只在内存参与兼容性判定，绝不写日志。

每项使用独立随机稳定 ID，以 items[{id,input}]、items[{id,result}] 封装。返回顺序不重要；未知/重复 ID 拒绝整包，缺失或结构无效项只单独回退一次。合法兄弟项先完成独立校验和就绪标记，再串行回退坏项，避免坏项等待耗尽已返回兄弟项的推理计时；合法兄弟项不重发。一个 Worker 取项批次内，所有外部提供商分组和本地分组共享最多 4 次自动单项回退；耗尽后该项标记 Deferred，不自动换提供商继续调用。普通规则流程仍会执行，已有正确规则结果可以正常归档；规则仍需 AI 的项持久化为失败，等待核对后重试。标题只出现在别项而不在本项时，改走本项单条回退；这只是额外防线，不是准确率保证。

外部复用各项原 schema/证据校验。本地只能返回本项原文闭集索引，JSON grammar 限定 ID 与索引值域，程序再按每项自己的候选池验证。没有跨文件补季、推身份、自动晋升候选等新权限。

批次按最终序列化 UTF-8 字节保守上界加输出预算检查；这不是厂商 token 的实际计数。超预算拆成更小请求，单项仍超预算则拒绝，不自动增大模型上下文。小模型最多 2 项且总预算不能超出现有 ContextTokens。HTTP 响应读入与 JSON 深度/大小均有上限。回退沿用同一项含排队时间的截止令牌；HTTP 429/网络故障不会在批量层立即扩成 N 次单条请求。

## 计量和验证

RPM 与调用额度在各协议完成节流、组包后，紧邻 HTTP 发送前检查并登记。等待节流期间取消时不登记；发起发送后的失败或取消保守计一次尝试。每次拆批、回退、重试都通过独立 DbContext 的条件 UPDATE 原子占用调用额度，网络期间不持数据库事务。一个共享 HTTP 请求只由一项记一次配额与完整 token；其他项保留各自审计记录但不重复扣配额。响应后立即补记 token，只结算一次且不重复增加调用次数；每次请求绑定其发送周期快照，迟到响应只给匹配周期补 token，终身累计始终保留。单项审计不包含兄弟项正文。

外部请求已通过逐项校验后，仅暂停其等待串行放行期间的内部推理/调用链计时；放行后恢复原链剩余预算，不重新开整链超时。未成功项的回退、真正晚到结果、用户和停机取消仍受原截止信号约束。本地辅助整体 15 秒查询预算不变。

诊断将 batchId/itemId 关联回各自解析 RunId，记录收集等待、物理请求数、回退项数、经过时间、实际 token（供应商提供时）与内存样本。内存样本不是峰值，估算 token 不是实际 token，不应将未记录值当作 0。

确定性测试使用合成桩，覆盖多文件一请求、乱序回配、缺项/重复/未知 ID、字段错误、跨项标题、预算拆单、限流、取消、重复暂停、作用域清理、诊断关联与真实 Worker 接缝。本地模型准确率/吞吐实验与这些契约测试分开报告；重建后的源码必须重新编译测试，旧环境通过记录不能替代新环境验收。


## DeepSeek 显式配置与容量

提供商目录接口 GET /api/settings/ai-batch/providers 仅在 HTTPS 官方 api.deepseek.com 根地址或 /v1、OpenAI 兼容协议及当前核验模型 deepseek-flash 同时匹配时提供预设。显示名称、代理网址、旧模型别名或其他模型都不会触发。官方能力表公布的 1,048,576 上下文和 393,216 输出只是模型上限，产品预设取更保守值：

| 显式选择 | 每批项数上限 | 上下文预算 | 输出预算 | 整个 HTTP 响应上限 |
| --- | ---: | ---: | ---: | ---: |
| 推荐非思考模式 | 32 | 65,536 | 32,768 | 1 MiB |
| 高级非思考模式 | 128 | 131,072 | 65,536 | 2 MiB |

来源：[官方模型列表](https://api-docs.deepseek.com/api/list-models/)、[官方模型能力](https://api-docs.deepseek.com/quick_start/pricing/)，2026-10-03 核查。独立 synthetic 脚本结果不等于产品或用户媒体的准确率保证。

预设只填表单草稿，必须显式保存。保存于现有 KV 的 providerSettings，每行绑定 providerId 和后端生成的 configurationKey（协议、端点、模型的哈希，不包含密钥）。模型或端点变化后覆盖失效，回到继承配置；过期且未编辑的行可保留，不影响修改其他配置。最多保存 16 行覆盖，整份 JSON 仍限制为既有字段的 4000 字符，不引入迁移。

这两个预设同时保存 disableThinking=true，且只有仍匹配的官方 OpenAI 兼容 DeepSeek 请求会发送 thinking.type=disabled。普通编辑或未选预设不会启用它；覆盖失效时非思考标记也不再应用。非思考模式与本轮独立实验保持一致，但并未进行新增真实模型调用。

自定义预算的产品硬界为上下文 1,048,576、输出 262,144、HTTP 响应 8 MiB。用户需要根据目标提供商能力显式配置，产品不宣称未知模型支持这些上限。maxResponseBytes 始终限制实际 HTTP envelope，不再对其乘倍数；解包文本同时受该边界约束。

每项输出预留按 schema 取 512 或 1024 token（其中预留封装空间），再按本项实际保留候选数每个增加 32。最终 JSON 转义后的输入、输出预留、预计响应大小以及批项数一起决定拆包。该预留无法保证模型为每项平均分配 token；供应商截断标记或无效 JSON/ID 会被拒绝，单项过大的响应只回退该项。合法 ID 下的 null result 只回退本项，不丢弃其他合法行；未知/重复 ID 仍拒绝整包并受 4 次回退总预算约束。

128 是调度与请求条数上限，并不保证每次都发 128 项。保守预设会按实际内容拆成更小请求。单项也放不进当前上下文/输出预算时明确报错，不能借“降级单条”绕过预算。

## 准备与诊断硬边界

单项解析输入最多 64 KiB；单次 Worker 最多 128 个独立 scope，合计待处理输入按最多 8 MiB 限定。实际进程占用还包含数据库对象、提示词、HTTP 及诊断；观察到准备阶段托管内存增幅达到 128 MiB 时提前排空当前波次，这个观测阈值不是进程内存峰值保证。

每组使用自己的批项数上限。本地达到 2 项即有机会发送，不会因某个外部配置 128 而先为 128 个本地项开启计时。出现后到的满组时先服务更早等待的部分组，并串行放行已经就绪的结果，再准备后面的文件；允许减少合批收益来保护原有等待预算。终止 Deferred 已确定后停止内部推理/链计时，真实用户或停机取消仍优先。

Full 诊断默认单 artifact 仍为 2 MiB。响应大于该上限、但小于传输上限时，媒体解析仍可读取完整 HTTP 正文，诊断 content 明确为 not_recorded / artifact_size_limit，捕获字节为 0，没有正文、原始内容哈希或 artifact；只记录 ObservedUtf8Bytes。超大的原文在隐私过滤前被拒绝捕获，不能把其大小冒充已脱敏正文大小。较小正文仍正常脱敏，过滤后继续复核 artifact 上限。
