# 边界声明式校验迁移（档2）—— 全量铺开记录

> 把 A 类「无状态字段校验」从 service 抛 `BusinessException` 改为请求 DTO 主构造参数上的 DataAnnotations，
> 由 `[ApiController]` 在模型绑定阶段统一校验，失败经 `ValidationEnvelopeFactory` → `{code:1000}` 信封（HTTP 200）。
> B/C/D/E/F（不存在 / 冲突 / 状态机 / 并发 / 外部失败 / 实体派生前置）一律保留在 service。

## 全局保守决策（KEEP，不迁移）
- `[AllowedValues]` 大小写敏感会破坏 service `ToLowerInvariant` 语义 → **mediaType / 日志 Level / 移动 Mode / DefaultType** 全 KEEP
- **集合长度**（items 空/超限、Events≥1）→ 本轮 KEEP（service 直测耦合 + IReadOnlyList 注解兼容存疑），留后续专项
- **JSON 合法性**（Conditions/ExtraOptions/LastRunResult）→ KEEP（需 `ex.Message`）
- **跨字段/条件式**（From>To、私有仓 PAT、权重和≈1、季+集、未指定记录、Items 三选一）→ KEEP
- **实体/派生前置**（Archive、Classify、ParsedInfo.* 等非入参）→ KEEP

## 后续三项完成（2026-06-05，VersionPrefix 0.35.2）

> 原「可选后续」三项已全部落地并验证（Host.Tests 189 / Application.Tests 382 / Infrastructure.Persistence.Tests 381 全绿）。

**关键结论（MVC 对 record 集合的校验行为，经 GeneralSettings 判别性实验确证）**：
- `[MinLength(n)]` / `[MaxLength(n)]` 挂在记录主构造参数（类型 `IReadOnlyList<T>`）上**有效**——运行时 `List<T>` 走 `ICollection.Count`。
- `[Required]` 挂集合参数可拦 null（JSON 省略 / 显式 null）。
- **MVC 会递归校验集合元素**：嵌套记录（如 `UpdateGeneralItem`）主构造参数上的 `[RequiredNotBlank]` 在元素遍历时被触发。
- 局限：`IReadOnlyList<string>` 的**字符串元素**无法逐个注解（只能整集合），故 Webhook「Event 名空/超长」逐元素校验仍留 `NormalizeEvents`（含 Trim+去重）。

**1. 集合长度校验注解化**：
- Review 四批量 DTO `Items` 加 `[Required]+[MinLength(1)]+[MaxLength(N)]`（N=50/50/500/500），删 `ReviewService` 4 段 count 检查 + 3 个常量；5 个 service 直测迁为反射单测。
- Webhook `Events` 加 `[Required]+[MinLength(1)]`，`NormalizeEvents` 改非空签名、删「至少 1 项」throw、保留逐元素校验。

**2. GeneralSettings 集合元素递归校验**：`Items` 加 `[Required]+[MinLength(1)]`、`UpdateGeneralItem.Key` 加 `[RequiredNotBlank]`；删 service「没有需要更新的配置项」「配置项 Key 不能为空」两处 throw（「受保护 key」KEEP）。

**3. MediaExtension Host e2e 补缺**：新增 `MediaExtensionsTests`（CRUD 闭环 + 必填/格式/唯一边界校验），补上该端点此前仅有 DTO 反射单测的集成覆盖缺口。
