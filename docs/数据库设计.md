# PersonalMediaManager 数据库设计

> 版本：v0.1.0
> 最后更新：2026-06-12
> 数据库：SQLite 单文件 `pmm.db`，EF Core 10 Code First 迁移
> 适用范围：本文展开当前实际 schema 的 **33 张表**（与 `Configurations/` 下 33 个 `IEntityTypeConfiguration<T>` / `PmmDbContext` 33 个 `DbSet` 一一对应）至字段级，给出 SQLite 类型/长度/可空/默认值/索引/约束，并附 EF Core DbContext 设计要点
>
> **表数演进说明：** 初版（需求文档 §4）规划 18 张；后续迭代陆续新增 ——「媒体库富化」一次性补 1 作品聚合 + 5 共享维度 + 5 连接表 + 季/集 2 表（共 13 张，详见文末「媒体库富化」章节；其历史迁移已并入 2026-06-11 Init 基线），另含 `Parse_TestCase`（解析回归测试集，§1.19）与 `System_MediaExtension`（受支持视频扩展名，§1.20）两张独立表，合计 **20 核心 + 13 富化 = 33 张**。本文 §一逐表展开核心 20 张（含两张新增），媒体库富化 13 张以文末汇总表概述其角色/关键列/约束
>
> **约定：**
> - 所有 `Id` 主键统一 `INTEGER` 自增（SQLite `AUTOINCREMENT`，EF 默认 `IDENTITY`）
> - 所有 `DateTimeOffset` 列（含 `CreatedAt` / `UpdatedAt` 等所有时间列）统一 `INTEGER`（用 `DateTimeOffsetToBinaryConverter` 转 Int64 binary，保留 Offset 信息；该转换已收敛进 2026-06-11 Init 基线迁移 `20260611125131_Init`），由 SaveChanges 拦截器自动写入；**实际值由 `TimestampInterceptor` 写入，列上无 SQL `DEFAULT` 子句**（数据库表 DDL 中 `CreatedAt`/`UpdatedAt` 不带 `DEFAULT CURRENT_TIMESTAMP`，本文表格里 `CURRENT_TIMESTAMP` 列仅作语义示意，详见 §3.7 拦截器章节）
> - 布尔列 `INTEGER`（0/1）
> - JSON 列 `TEXT`，EF 走 `HasConversion` + `ValueComparer`（清单见 §3.4）
> - 加密列以 `Encrypted` 结尾，存 DataProtection 输出的 Base64 字符串
> - 索引列名以 `IX_{表名}_{列}`；唯一约束以 `UQ_{表名}_{列}`；外键以 `FK_{表名}_{父表}_{列}`
> - **`TEXT` 列大小写敏感性**：SQLite 默认 collation 为 `BINARY`（字节级精确比较，大小写敏感）。所有标记为 `UQ` 的字符串唯一列（如 `Watch_Folder.Path`、`Parse_Rule.Name`、`Category_Definition.Name`、`User_Account.Username` 等）在不显式 `COLLATE NOCASE` 时 `'foo'` 与 `'FOO'` 视为两条不同记录；EF 配置如需大小写不敏感唯一性须 `b.Property(x => x.X).UseCollation("NOCASE")`，**当前所有表均沿用默认 BINARY**（路径区分大小写、用户名区分大小写均符合 §需求文档行为约定）

### 3.3 OnModelCreating 要点

每个实体一个 `IEntityTypeConfiguration<T>` 配置类，集中定义表名/索引/约束/转换器；`OnModelCreating` 内统一 `modelBuilder.ApplyConfigurationsFromAssembly(...)`。

**关键配置示例（以 `MediaItem` 为例）：**

```csharp
public sealed class MediaItemConfig : IEntityTypeConfiguration<MediaItem>
{
    public void Configure(EntityTypeBuilder<MediaItem> b)
    {
        b.ToTable("Media_Item");                                           // 严格对齐表名
        b.HasKey(x => x.Id);

        b.Property(x => x.SourcePath).HasMaxLength(1000).IsRequired();
        b.HasIndex(x => x.SourcePath).IsUnique().HasDatabaseName("UQ_Media_Item_SourcePath");
        b.HasIndex(x => new { x.Status, x.CreatedAt }).HasDatabaseName("IX_Media_Item_Status_CreatedAt");

        // 枚举存为 INTEGER（默认行为，显式声明便于阅读）
        b.Property(x => x.Status).HasConversion<int>();

        // JSON 列：ParsedInfo —— CLR 类型即 string?（Domain 层 ParsedInfo 值对象自行 ToJson()/FromJson()），
        // 不走 Converter；显式 ValueComparer<string?> 锁定按字符串值比较，避免 EF 默认引用比较误判变更
        b.Property(x => x.ParsedInfo)
         .HasMaxLength(2000)
         .Metadata.SetValueComparer(new ValueComparer<string?>(
             (a, b) => a == b,
             v => v == null ? 0 : v.GetHashCode(),
             v => v));

        // 乐观并发
        b.Property(x => x.RowVersion).IsConcurrencyToken().HasDefaultValue(0L);

        b.HasOne<CategoryDefinition>()
         .WithMany()
         .HasForeignKey(x => x.CategoryId)
         .OnDelete(DeleteBehavior.SetNull);
    }
}
```

### 3.4 JSON 列统一处理

提供通用 `JsonValueComparer<T>`，避免 EF 变更追踪误判：

```csharp
public static class JsonValueComparer<T>
{
    public static readonly ValueComparer<T?> Instance = new(
        (a, b) => JsonSerializer.Serialize(a, JsonOpts.Default)
               == JsonSerializer.Serialize(b, JsonOpts.Default),
        v => v == null ? 0 : JsonSerializer.Serialize(v, JsonOpts.Default).GetHashCode(),
        v => v == null ? default : JsonSerializer.Deserialize<T>(
                                    JsonSerializer.Serialize(v, JsonOpts.Default), JsonOpts.Default));
}

public static class JsonOpts
{
    public static readonly JsonSerializerOptions Default = new()
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull,
        Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping
    };
}
```

**涉及 JSON 列（汇总清单 · 共 15 列；r3 P3-r3.7 建档，2026-06-12 补齐）：**

| 表 | 列 | CLR 实体类型 | 持久化策略 | 备注 |
|---|---|---|---|---|
| `Media_Item` | `ParsedInfo` | `string?`（已是 JSON 文本） | `ValueComparer<string?>`（按值比较）+ `HasMaxLength(2000)` | Domain `ParsedInfo` 值对象自行 ToJson/FromJson，DB 列只存原文字符串 |
| `Tmdb_MetadataCache` | `Genres` | `List<TmdbGenreEntry>` | `JsonValueConverter<List<...>> + JsonValueComparer<List<...>>` | TMDB 题材列表（中英双值） |
| `Tmdb_MetadataCache` | `OriginCountry` | `List<string>?` | `JsonValueConverter<List<string>> + JsonValueComparer<List<string>>` | 出品国列表（可空，r3 第一波已修对称性） |
| `Tmdb_SearchCache` | `Results` | `List<TmdbSearchResultEntry>` | `JsonValueConverter + JsonValueComparer` | TMDB 搜索候选列表（按查询关键字缓存） |
| `Category_MatchRule` | `Conditions` | `CategoryMatchConditionTree` | `JsonValueConverter + JsonValueComparer` | 分类匹配条件树（递归 AND/OR/leaf） |
| `Webhook_Subscription` | `Events` | `List<string>` | `JsonValueConverter + JsonValueComparer` | 订阅的事件类型列表（如 `["MediaArchived"]`） |
| `Webhook_Delivery` | `Payload` | `string`（已是 JSON 请求体原文） | `ValueComparer<string>`（按值比较，重投时整体覆盖） | 出站请求体原文 |
| `Audit_Operation` | `Detail` | `Dictionary<string, object?>?` | `JsonValueConverter + JsonValueComparer` | 操作附加上下文（灵活字段） |
| `Parse_AiProvider` | `ExtraOptions` | `Dictionary<string, string>?` | `JsonValueConverter + JsonValueComparer` | AI 提供商扩展配置（temperature 等） |
| `Media_Item` | `TmdbCandidatesJson` | `string?`（已是 JSON 文本） | `ValueComparer<string?>`（按值比较）+ `HasMaxLength(4000)` | 人工复核 TMDB 候选快照，Domain 不解析 |
| `Parse_TestCase` | `LastRunResult` | `string?`（已是 JSON 文本） | `ValueComparer<string?>` + `HasMaxLength(2000)` | 最近一次回归实测结果，Domain 不解析 |
| `Parse_TestCase` | `AiVerdict` | `string?`（已是 JSON 文本） | `ValueComparer<string?>` + `HasMaxLength(2000)` | AI 判定结果（暂存区 Triage 产生） |
| `Audit_ScheduledTaskRun` | `DetailJson` | `string?`（已是 JSON 文本） | `ValueComparer<string?>` + `HasMaxLength(2000)` | 调度任务附加上下文，Recorder 自行序列化 |
| `Process_Step` | `Detail` | `string?`（已是 JSON 文本） | 仅 `HasMaxLength(8000)`，无 Comparer（append-only 子表，行只插不改，无变更追踪需求） | Stage-specific 结构化 JSON，前端按 Stage 渲染 |
| `Media_Work` | `OriginCountry` | `List<string>?` | `JsonValueConverter<List<string>> + JsonValueComparer<List<string>>` | 出品国列表（富化标量，参照 `Tmdb_MetadataCache` 同名列） |

> **收录口径：** 凡「列内容为 JSON 文本」一律入本表，无论持久化策略是「Converter + 强类型」还是「原文 string + ValueComparer」，亦含 append-only 表上无 Comparer 的纯 JSON 文本列（`Process_Step.Detail`）；仅 `Tmdb_MetadataCache.RawJson`（原始响应整包存档，只写不参与变更比较）不计。计 15 列。新增 JSON 列时按本表风格扩展并同步：1) Domain 实体属性；2) Configuration 持久化策略（Converter/Comparer 按需）；3) §1 表定义注 `JSON`；4) 本表追加一行。
> 选择「ValueComparer + 原文 string」而非「Converter + 强类型」的列（`ParsedInfo` / `Payload` / `TmdbCandidatesJson` / `LastRunResult` / `AiVerdict` / `DetailJson`）原因：上层语义已经持有原文 JSON 字符串（值对象自序列化 / 请求体原文整体存档 / 快照不解析），再走 Converter 反序列化纯属冗余。

### 3.6 DataProtection 加密字段

加密走应用层而非 EF 转换器，目的：**密钥环可访问性**与 EF 的迁移/查询解耦。

提供 `IProtectedFieldService`：

```csharp
public interface IProtectedFieldService
{
    string? Protect(string? plaintext);
    string? Unprotect(string? ciphertext);
}
```

**涉及字段：**
- `Parse_AiProvider.ApiKeyEncrypted`
- `Tmdb_Setting.ApiKeyEncrypted`
- `Webhook_Subscription.SecretEncrypted`
- `System_Setting` 键 `Update_GitHubPat` 的 `Value`（GitHub PAT，客户端升级检查端点用）——经 `IProtectedFieldService` 加密后落库，与 TMDB ApiKey / AI Provider ApiKey 同级安全模式；KV 通用表列名无 `Encrypted` 后缀，读写仅经 `UpdateSettingService` 加解密通道，禁止明文 KV 直写绕过加密

**调用约定：** 仅在 Repository / Service 边界 protect/unprotect；实体类持有的字段名以 `Encrypted` 结尾（KV 表的 `Update_GitHubPat` 例外，以键名 + 专属服务通道约束），避免误用明文。

**密钥环位置（产品仅支持 Windows，macOS 支持已移除）：**
- Windows：`%LocalAppData%\PersonalMediaManager\keys`
- 启动时 `Directory.CreateDirectory` 确保存在；权限收紧（仅当前用户可读）

### 3.7 SaveChanges 拦截器

实现 `SaveChangesInterceptor`，统一维护：

1. `CreatedAt` / `UpdatedAt`：`Added` 行设两者，`Modified` 行仅设 `UpdatedAt`
2. `RowVersion`：`Modified` 行 `+= 1`（与 `IsConcurrencyToken` 配合实现乐观锁）
3. 审计：对配置中标记的实体变更写 `Audit_Operation`

> **r3 P3-r3.5 文档修正**：本文 §一各表格里 `CreatedAt` / `UpdatedAt` 列的「默认值」栏写作 `CURRENT_TIMESTAMP` 仅是**语义示意**（表达「自动填写当前时间」），并不是真实的 SQL `DEFAULT` 子句。实际 DDL 中这两列**没有任何 SQL 默认值**，时间戳完全由 `TimestampInterceptor` 在 `SaveChanges` 时写入 `INTEGER`（Int64 binary，含 Offset 信息）。直接走 SQL `INSERT` 跳过 EF 拦截器会让这两列写入 0；如需脚本手工建数据，请显式补 `strftime('%s','now')` 之类的 epoch 值或通过 EF 入库。

```csharp
builder.Services.AddSingleton<TimestampInterceptor>();
builder.Services.AddSingleton<RowVersionInterceptor>();
builder.Services.AddDbContextFactory<PmmDbContext>((sp, opt) =>
    opt.UseSqlite(...)
       .AddInterceptors(sp.GetRequiredService<TimestampInterceptor>(),
                        sp.GetRequiredService<RowVersionInterceptor>()));
```

## 媒体库富化（历史迁移已并入 2026-06-11 Init 基线）

为「丰富媒体信息 / 剧集分季分集 / 关联信息搜索」新增 1 个作品聚合 + 5 个共享维度 + 5 张连接表 + 季/集 2 张表（共 13 张），并给 `Media_Item` 加 2 列存在性标记。

| 表名 | 实体类 | 角色 | 关键列 / 约束 |
|---|---|---|---|
| `Media_Work` | `MediaWork`（聚合根） | 按 TMDB 作品聚合的库内持久实体 + 富化标量 | UQ`(TmdbId,MediaType)`；标量 Title/Overview/Tagline/Backdrop/Runtime/VoteAverage/ReleaseDate/TmdbStatus/OriginCountry(JSON)/TotalSeasons/EnrichedAt…；FK CategoryId→Category_Definition(SetNull)；RowVersion 乐观并发 |
| `Media_Person` | `MediaPerson` | 人员维度（演员/剧组共享） | PK=TMDB person id（不自增） |
| `Media_Genre` | `MediaGenre` | 类型维度 | PK=TMDB genre id |
| `Media_Company` | `MediaCompany` | 制作公司维度 | PK=TMDB company id；LogoPath/OriginCountry |
| `Media_Network` | `MediaNetwork` | 电视台维度（剧集） | PK=TMDB network id |

设计要点：维度实体按 TMDB id 跨作品共享（同演员仅一行，支撑「按人/类型/公司检索全库」的 join）；连接表与季/集随 `Media_Work` 级联，由聚合 `Replace*` 原子替换（充血聚合纪律）；富化数据 TTL 复用 `Tmdb_Setting.MetadataCacheHours`，与解析管线的 `Tmdb_MetadataCache`（短期缓存）解耦。
