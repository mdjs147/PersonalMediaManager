# 目录范围标题边界候选

本页说明目录范围与当前文件集号之间的证据约束，避免将目录批次范围混入作品标题。

## 合成示例与预期

以下合成命名形态用于规则回归，不对应原始媒体文件。

- 文件名：`21.720p.HD粤语中字无水印[最新电影www.example.test].mkv`
- 直接父目录：`测试剧名21-22.720p`
- 预期标题：`测试剧名`
- 文件集号：`Episode=21`、`EpisodeEnd=null`
- 季号和年份保持未知；目录的 `21-22` 不证明季号，也不表示当前文件包含两集

## 新增因素及边界

在目录原始字符串上、分隔符折叠之前识别一个尾部数字范围。必须同时满足以下条件才允许将其作为标题边界：

1. 起止数字均为 1–3 位，起点大于 0，终点大于起点；范围连接符为 `-`、`~` 或 `–`
2. 当前集落在范围内，且文件本身有独立、无小数的单集证据：现有 S/E/中文集号/方括号语法，或现有纯数字/数字加分辨率兜底
3. 不接受只从父目录或用户规则结果得到的集号，也不为文件的多集范围新增此标题处理
4. 范围前仍是有身份意义的标题；范围后仅剩已知技术噪声。未知正文、反向范围、相等端点、范围外集号及过长数字均不启用此因素

只改变内置主标题和目录备选标题的提取，不修改 Episode、EpisodeEnd、Season、年份、AI 提示/schema、契约或持久化结构。保留用户规则捕获的主标题；强制电影规则不启用此目录候选处理。标题内部的续作数字不删除，数字电影标题 `1917`、`1984` 不作为文件集号。

正则没有任何作品名称映射，也不从已折叠空白中的两个数字反向猜范围。目录范围信息只用于局部标题边界，不写入文件多集证据。
