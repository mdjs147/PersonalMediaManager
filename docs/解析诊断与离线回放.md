# 解析诊断与离线回放

本功能仍属于产品 0.4.0；事件 `schemaVersion: 1` 是数据格式标记，不是独立产品版本。无需数据库迁移。诊断仅写入本机应用日志目录的 `parse-diagnostics` 子目录，不自动上传，不把真实用户日志加入仓库。

## 已记录的链路

- 每次扫描拥有 `scanRunId`；经过队列时显式复制关联，不依赖异步线程继承。重启恢复或旧入口无法知道原扫描 ID 时为 `null`，不得猜测
- 每次单文件处理另建 `runId`，重试/重扫不会混入上一次运行；建行后关联 `mediaItemId`，事件有递增 `sequence` 与时间戳
- 输入保存文件名、监控根以内的相对目录段、输入目录上下文来源、文件大小、元信息是否可用。默认不保存绝对目录、用户主目录、凭据或请求头
- `rule.result` 保存完整返回契约中的规则结果、字段证据、冲突、拒绝字段、命名/编号候选，以及规则引擎提供的有界执行轨迹。未合入新规则轨迹的旧构建不会伪造该字段
- TMDB 每次搜索、详情、剧集组查询保存请求语义、返回候选/目录、耗时和异常；候选排序、临时选中来源和随后类型/目录守门结论由管线阶段事件连接
- AI 保存实际模型、协议、参数、System/User 提示词指纹、响应捕获状态、tokens、耗时、取消、重试、校验结果。指纹针对脱敏后的内容，不表示厂商模型权重指纹。远程厂商没有提供的服务端版本标为未记录，不伪造
- 本地 AI 另记运行参数、模型 ID、目录登记的预期工件 SHA256/修订（启动时核验，不额外逐请求读完整模型）、缓存命中和取消。Gemini `thought:true`、reasoning/thinking 字段与已识别的私有推理标签不保存
- 人工确认/改绑保存旧→新、来源 `ReviewApi`、已准备/已提交状态；调用者身份未知时为 `unknown`。`groundTruth:false` 明确人工修正不是自动识别真值
- 主流程故障、取消、终态及耗时都有事件。诊断写入失败不改变媒体处理结果；导出包含当前存储写入失败计数。进程崩溃造成的未结束运行不会被补成成功

## 级别与容量

在应用数据目录的 `local.json` 合并以下配置，重启生效；同名环境变量可用双下划线分隔，例如 `ParseDiagnostics__Level=Detailed`。不要覆盖已有的其它配置。

```json
{
  "ParseDiagnostics": {
    "Level": "Standard",
    "MaxTextUtf8Bytes": 16384,
    "MaxEventUtf8Bytes": 65536,
    "MaxFileBytes": 4194304,
    "MaxTotalBytes": 33554432,
    "RetentionDays": 7,
    "MaxFiles": 16
  }
}
```

- `Off`：不写结构化诊断文件；已有数据库调用统计保留，原文只保存未记录提示
- `Standard`（默认）：记录结构化决策、相对文件输入、模型、长度与指纹；AI 提示词/响应正文不落盘
- `Detailed`：增加脱敏后的实际提示词和响应正文，用于短期诊断；默认每段最多 16KiB，建议完成复现后切回 Standard

所有级别都会过滤密钥、认证头、cookies、URL 用户信息/查询参数、已识别私有推理与绝对路径。未能安全解析含敏感字段的截断 JSON 会关闭式省略。相对目录、文件名、作品名本身仍可能是私人信息，导出前应人工检查，不宜上传公开问题库。

正文长度按脱敏后的 UTF-8 字节计，截断不拆 Unicode 标量；每段含 `state/text/sha256/originalUtf8Bytes/capturedUtf8Bytes/truncated/redacted`。`dataRedacted` 说明其它结构化字段被过滤。整事件超限时保留关联信封并将 data 标为 `not_recorded` + `event_size_limit`，不生成损坏 JSON。

文件按日期/容量轮转，每次写入执行天数、总容量、文件数约束。只清理专用目录中由接收器命名的 `parse-*.jsonl`，不触碰媒体、原始数据、模型、普通应用日志或备份。Unix 新诊断目录/文件分别限定当前用户 0700/0600；Windows 继承应用数据目录访问控制。磁盘满或写入拒绝时业务继续。

## 本机授权导出

仅 Admin 可访问（匿名 401、Viewer 403）。接口不接收文件路径，只接受一个 ID：

- `GET /api/diagnostics/parse/export?mediaItemId=42`：该媒体保留窗口中的各次运行，包括绑定媒体 ID 前的初始事件
- `GET /api/diagnostics/parse/export?runId=<32位十六进制>`：一次运行
- `GET /api/diagnostics/parse/export?scanRunId=<32位十六进制>`：一次扫描及已关联的媒体处理

响应为既有 API 信封，`data.events` 为时间排序事件，`data.completeness.runs` 逐运行报告输入是否可重建，区分扫描、人工审核等不适用运行。导出最多 16MiB/20,000 事件，读取源日志最多 32MiB/50,000 事件，超限显式标记；不会从备份或媒体目录偷偷补取内容。导出时再应用当前隐私过滤。

`completePipelineReplay` 始终为 `false`：数据留存、脱敏、截断、模型随机性、外部 TMDB 变化都可能让完整重放不成立。

## 提取规则回归输入

将授权导出响应保存到本地，然后运行：

```bash
python scripts/parse-diagnostics-replay.py export.json replay-inputs.json
```

脚本完全离线，输出文件必须不存在，不会覆盖原日志或源数据。它仅接受明确 `recorded` 且未截断/未脱敏的文件名与目录段；缺口逐运行列入 `rejected`，不会用空值代替。输出包含规则输入、记录结果及人工变更，并保持 `groundTruth:false`。测试仓库只能提交合成/已授权且去隐私的 fixture。

重新跑规则时应使用相同构建及规则配置，将 `fileName` 和 `relativeSegments` 构造为 `FileParseContext`，保留记录结果作为对照而不是正确答案。自定义规则只记录 ID/内容 hash，不保存正则正文；精确复现自定义规则需用户另行提供该配置。Detailed 的提示词可帮助诊断，但脚本不会自动重放真实模型或 TMDB 调用。

状态语义：`not_recorded`=策略未保存，`missing`=已观察为空，`unknown`=未能观察。缺少事件还可能是已过期、未完成或写入失败；这些状态不等于“没有问题”。
