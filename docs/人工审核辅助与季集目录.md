# 人工审核辅助与季集目录

## 安全边界

- 库内推荐、规则提取和累计编号映射均为预览，不修改绑定、不改名、不归档、不调用 AI
- 推荐身份键为 `(mediaType, tmdbId)`；电影和剧集即使数字 ID 相同也互不复用
- 库内候选按当前身份/目录与标题上下文、标题或原名相似、近期未完结作品排序，仍须人工选择
- 规则重新提取仅读取服务端记录、监控范围及本地规则，返回局部原文证据和冲突，不向 TMDB 发送媒体路径
- 原未绑定记录可用人工显式所选 TV 身份预览，须显示该身份未经源文件自动验证；原已绑定不同作品或类型时仍阻断。预览令牌绑定源记录快照及所选身份
- 用户声明“源编号为全剧累计集号”后，才可请求换算预览。已明确标注季内编号（如 `S02E14`）的文件不自动扣减前季集数
- 特别篇、附加内容、未核实版本（如 HD Remaster）及已有编组映射的记录不使用标准累计换算；需人工核对填写
- 前季必须具备同一 TV 身份、完整无重复的逐集目录，且播出时间已知、不含未播集；不能仅从 `seasons[].episode_count` 机械相减
- 特别篇不计入普通季累计序。目标季目录缺失、编号超界、跨季合并文件、目录刷新失败或身份冲突均阻断换算
- 映射返回原编号、目标编号、逐季核验依据及缓存时间。应用表单后，确认请求还要提交原编号和预览令牌；后端在所选季刷新之后重新核验，依据变化须重做预览
- 保存人工确认时保留 `decisionSource`、旧新值、目录来源/时间；映射后的 `OriginalEpisode` 保留源命名空间，用于字幕伴生匹配。人工记录不当作自动解析金标准

## 接口补充

`POST /review/episode-hints` 输入 `items: [{id, rowVersion}]`，最多 100 条；输出 `items: [{id, season, episode, episodeEnd, source, evidence, error}]`。单条冲突不覆盖原表单。

`GET /review/{id}/library-candidates?query=...` 输出 `items`，每项含作品类型与 ID、标题/原名、海报、年份、季数、`source`、`matchReason`、`tmdbStatus`、最近归档时间。结果不改变该条媒体的绑定。

`POST /review/episode-mapping-preview` 输入 `tmdbId, mediaType:"tv", season`（目标季）及 `items:[{id,rowVersion,episode,episodeEnd}]`。`forceRefresh` 可强制重拉目录；重复记录拒绝。输出逐项原编号、目标季集及 `evidence/error/mappingToken`。

确认接口增加 `decisionSource`（`ManualForm/RuleExtraction/BatchFill/AbsoluteMapping/LibrarySelection`）、`sourceEpisode/sourceEpisodeEnd/mappingToken`。更改映射目标、作品或编号后须废弃令牌并重新预览，或作为手工填写明确确认。

`GET /review/{id}/tmdb-detail` 增加 `season`、`forceRefresh`。作品详情和 `catalogue`（所选季逐集资料）各自返回 `cachedAt/fromCache/refreshError`。未播集或缺简介如实保留为空，不生成虚构内容。

人工确认和显式改绑会刷新作品及所选季，并同步库内资料。无有效详情缓存且远端失败时禁止验证该绑定。已有缓存失败回退保留原缓存时间并显示错误；单条确认通过 `metadataRefreshError`、批量通过 `metadataWarnings` 返回资料刷新警告。

库内作品强制刷新不清空已有分集。季目录按配置 TTL 更新；成功返回但简介为空时，库内显示可保留旧好简介，原始目录仍保持真实响应，不能用合并后的库内资料冒充新目录证据。

## 验证口径

使用合成同构连续剧、SQLite 内存库、规则与 TMDB mock。没有连接用户当前媒体库或调用真实 TMDB，因此不宣称已验证任何特定剧的当前总季数、逐集目录或发行集序。历史人工调整只能用作问题线索，不能证明一个通用累计偏移量。
