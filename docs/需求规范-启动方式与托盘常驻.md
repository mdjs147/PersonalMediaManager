# 启动方式与托盘常驻 — 需求规范

> 版本：v0.6
> 最后更新：2026-06-11
> 上游依据：`CLAUDE.md` §一 §十二、`docs/开发计划.md` §E.1
> 适用对象：PersonalMediaManager.Launcher 完整化（阶段 E 末或 F 收口阶段）
> 平台范围：**本产品仅支持 Windows**（macOS 支持已于 2026-06-11 决策移除，不在路线图，详见 §十一）；本规范全文按 Windows 描述。

---

## 〇、目标形态

* **单一可执行文件**（`PersonalMediaManager.exe`），默认以「桌面常驻 + 内嵌 Web 服务」形态运行。
* **同进程**承载 WinForms 托盘 UI + ASP.NET Core Kestrel（同生命周期、同配置链路）。
* Web/业务装配由 `PersonalMediaManager.Host.Composition.PmmHost.CreateApp(args, paths) → WebApplication` 提供，供 Launcher 与测试夹具共用；本规范一律称该工厂为 `PmmHost.CreateApp`。

---

## 一、进程启动

### 1.1 入口约定

* `Launcher.csproj`：`<OutputType>Exe</OutputType>` + `<UseWindowsForms>true</UseWindowsForms>`（已配）。**待补**：`<ApplicationHighDpiMode>PerMonitorV2</ApplicationHighDpiMode>`。
* `Program.cs` 从 top-level statements **重构**为：
  * `[STAThread] static int Main(string[] args)`
  * `ApplicationConfiguration.Initialize()`
  * `Application.Run(new PmmTrayContext(args, paths, hostFactory))`
* 用 `ApplicationContext` 子类 `PmmTrayContext` 持有托盘，**不**用 `Form`：无主窗口、退出时间点由 `ExitThread()` 控制。

### 1.2 命令行参数

仅一条：`--autostart`（大小写不敏感）。语义只一条 —— **启动后不弹气泡**。其它行为完全不变（仍启 Kestrel、仍装托盘、仍 Migration）。

解析：`args.Any(a => string.Equals(a, "--autostart", StringComparison.OrdinalIgnoreCase))`，不引第三方参数库。

### 1.3 启动期致命错误兜底

`Application.Run` 外层 `try/catch`：

* 异常 `ToString()` 写入 `<AppPaths.Root>\tray-crash.log`（即「程序目录\data\tray-crash.log」，回退 `%LocalAppData%\PersonalMediaManager\`）。写文件失败再吞，不升级。
* 同时 `MessageBox.Show` 让用户看到原因，**绝不**静默崩。
* `finally` 调 `Log.CloseAndFlush()`（PmmHost 内部已配 Serilog，外层幂等再调一次兜底）。

## 二、数据目录

**绿色软件形态**：所有可写文件（db / logs / keyring / posters / local.json / tray-crash.log）落 `AppPaths.Root`。Windows 优先「程序目录\data\」（取 `Environment.ProcessPath` 的 exe 真实所在目录 + `\data`，数据跟随程序，整目录可备份/迁移/卸载）；写探针校验不可写（如装入 `C:\Program Files\`）时回退 `%LocalAppData%\PersonalMediaManager\`。非 Windows 平台仅保留通用兜底路径（`~/.local/share/PersonalMediaManager`），不构成支持承诺（产品仅支持 Windows）。

* 不锚定 `Environment.CurrentDirectory`（PMM 无相对路径依赖）。
* wwwroot / appsettings.json 已**嵌入 Host 程序集**（`GenerateEmbeddedFilesManifest` + `ManifestEmbeddedFileProvider`），随单文件 exe 内置、内存直读，不再依赖 `ContentRootPath` 解析外置散文件。
* `Environment.ProcessPath` 既用于「开机自启」拼命令行，也用作**数据目录基准**（取 exe 真实所在目录 → `\data\`）。

> 单文件发布下 `AppContext.BaseDirectory` 是 `%TEMP%\.net\<App>\<hash>\` 解压目录，OS 可清理、且每次升级 hash 变 → 落数据绝对禁止。数据目录必须走 `AppPaths`（基于 `Environment.ProcessPath` 的程序目录\data），而非 `BaseDirectory`。

## 三、配置链路

### 3.1 两层 JSON

* `appsettings.json`：出厂默认，**嵌入 Host 程序集**（随单文件 exe 内置，只读），由 `PmmHost` 经 `ManifestEmbeddedFileProvider` 读 → `AddJsonStream` 注入最低优先级。
* `<AppPaths.Root>\local.json`：本地覆盖层（程序目录\data\local.json），schema 与 appsettings 同构。

加载顺序（由低到高）：
```
appsettings.json（嵌入 Host 程序集，AddJsonStream 注入）
appsettings.{Environment}.json
<程序目录\data>\local.json     ← 必须绝对路径接入（回退 %LocalAppData%\PersonalMediaManager\）
环境变量
命令行参数
```

### 3.2 接入方式

`PmmHost.CreateApp` 内：
```csharp
WebApplicationBuilder builder = WebApplication.CreateBuilder(options);
string localConfigPath = Path.Combine(paths.Root, "local.json");
builder.Configuration.AddJsonFile(localConfigPath, optional: true, reloadOnChange: false);
```

> 必须**绝对路径**：`builder.Configuration` 默认根目录是 `ContentRootPath`（= 单文件解压目录），而 local.json 在数据目录（程序目录\data），相对路径会找错位置。

### 3.3 仅 2 项可覆盖（pre-boot 必需）

| 字段 | 含义 | 默认 |
|---|---|---|
| `Web:Port` | Kestrel 监听端口 | `PmmHost.DefaultPort`：Release 7288 / Debug 47333（调试端口错开正式环境，避免本机双实例抢端口） |
| `ConnectionStrings:Default` | SQLite 连接串 | 由 `AppPaths.DbFile` 派生 |

> **设计原则**：只有「**没启 Kestrel 之前就要解析**」的配置走 local.json；其它运行期可改项（TMDB Key / AI Provider / 日志级别等）走数据库 `System_Setting` 表（C 阶段已规划） + 重启生效。避免双轨制覆盖。

### 3.4 读写工具：`LocalConfigStore`

位于 `PersonalMediaManager.Launcher.LocalConfigStore`（静态类，不依赖 `IConfiguration`，让 Tray 无 DI 上下文也能用；所有方法显式传入 `AppPaths`，避免静态字段持有路径导致测试串扰）。API：

```csharp
int?    ReadOverridePort(AppPaths paths);
void    SetOverridePort(AppPaths paths, int port);
void    ClearOverridePort(AppPaths paths);

string? ReadOverrideDbPath(AppPaths paths);
void    SetOverrideDbPath(AppPaths paths, string dbPath);
void    ClearOverrideDbPath(AppPaths paths);

int     ResolveEffectivePort(AppPaths paths);   // 优先 local.json，回退 PmmHost.DefaultPort

string? ReadLastBalloonedVersion(AppPaths paths);                 // 非 override：更新提示气泡的版本去重记录
void    SetLastBalloonedVersion(AppPaths paths, string version);  // 同版本只弹一次升级气泡
```

实现要点：
* **写入**：就地解析 → 修改对应节 → 写回，保留其它节。
* **清空**：清字段后若所在节空了删节；整文件空了删文件。
* **异常**：`IOException` / `JsonException` / `UnauthorizedAccessException` 一律按「无覆盖」吞掉，**绝不**阻断启动。
* **JSON 损坏**：覆盖式 setter 直接重写。

### 3.5 校验：`LocalConfigStore.TryValidate*(candidate, out error)`

| 类型 | 校验 |
|---|---|
| 端口 | 1–65535；当前未被监听（`IPGlobalProperties.GetActiveTcpListeners`）|
| db 路径 | 绝对路径；父目录存在；父目录可写探测（写 `.pmm-write-probe` 临时文件再删）|

> **不**校验 db 文件后缀（PMM 不强制 `.db`）。
> **不**校验 db 是否已存在 —— 切到不存在的路径时 EF Migration 会自动建 schema，但因无业务数据，所有业务接口被 `SetupGuard` 拦回到初始化向导（见 §6.4 边界）。

## 四、托盘 UI

### 4.1 NotifyIcon 基础

* `notifyIcon.Text`：`PersonalMediaManager <version> · <状态文案>`，状态切换时实时刷新（Windows 上限 127 字符，超长截到 60 + `…`）。
* 版本号：`AssemblyInformationalVersionAttribute` 截掉 `+commit` / `-pre` 后缀，回退 `AssemblyVersion`，兜底 `v0.0.0`。
* 左键单击图标 = 打开 WebUI。
* 右键单击：弹 `ContextMenuStrip`。

### 4.2 图标方案

**程序化绘制**（沿用 PMM 现状，无外部 .ico 资源）：

* 状态保留 PMM 现有 5 个：`Running` / `Stopped` / `Paused` / `Syncing` / `Error`（接口 `TrayIconState` 已定义）。
* **仅** `Running` / `Stopped` 两个常态做 light/dark 主题区分（用户感知最高的两个状态），其余 3 状态不分主题。共缓存 **7** 个 `Icon` 实例：`Running-Light / Running-Dark / Stopped-Light / Stopped-Dark / Paused / Syncing / Error`。
* 主题判断：读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` 下 `SystemUsesLightTheme`（0=深色任务栏，1=浅色）。读不到默认按深色。
* 监听 `Microsoft.Win32.SystemEvents.UserPreferenceChanged`，`Category == General` 时重读，主题真变了才切。
* **Dispose 时务必反订阅 `SystemEvents.UserPreferenceChanged`**（静态全局事件，不反订阅会泄漏整个 `PmmTrayContext`）。
* Dispose 自有 `Icon`；`SystemIcons.Application` 是单例不可释放，用 `ReferenceEquals` 排除。

### 4.3 主题事件线程安全

`UserPreferenceChanged` 可能在非 UI 线程触发：
* 构造时抓 `SynchronizationContext.Current`，有就 `ctx.Post(_ => UpdateIcon(), null)` 回 UI 线程。
* 没有就直接更新（`NotifyIcon` 内部会 marshal）。

### 4.4 菜单结构

```
PersonalMediaManager <version>          (灰色禁用，标识项)
─────────────────
启动运行 / 停止运行                 (按当前状态切换文案)
打开 WebUI                          (运行时可点；未运行时禁用)
复制访问地址                        (运行时可点；未运行时禁用)
扫描硬盘                            (运行时可点；扫描全部已启用监控目录)
─────────────────
配置端口…
配置数据库位置…
开机自动启动                        (checkable，反映当前注册表状态)
─────────────────
退出
```

> **已落地**：`PmmTrayContext.RebuildTrayMenu()` 已实现上述完整菜单；「扫描硬盘」复用 `IScanService.TriggerAllAsync(false)` 扫描全部已启用监控目录，扫描期间禁用重复点击，停止服务时取消并等待扫描释放作用域。

## 五、内嵌 Kestrel 生命周期

### 5.1 启动

```csharp
WebApplication app = await Task.Run(() => PmmHost.CreateApp(launchArgs, paths));
Task runTask = Task.Run(() => app.RunAsync());
```

* `Task.Run` 隔离到线程池：WinForms `SynchronizationContext` 不参与 → 避免 `RunAsync` 的 continuation 抢占 UI 线程、避免 `.Wait()` / `.GetAwaiter().GetResult()` 与 UI 同步上下文死锁。
* 构造时 fire-and-forget（`_ = StartWebAppAsync()`），UI 不阻塞；启动结果通过菜单状态 + 气泡反馈。
* 启动失败：保留托盘存在，菜单显示「已停止」，允许用户改端口/退出。

> **已落地**：`PmmTrayContext` 已按本节实现异步启停（`StartWebAppAsync` / `StopWebAppAsync`）。

### 5.2 停止

```csharp
using CancellationTokenSource cts = new(TimeSpan.FromSeconds(5));
try { await app.StopAsync(cts.Token); } catch (OperationCanceledException) { }
await Task.WhenAny(runTask, Task.Delay(TimeSpan.FromSeconds(5)));
await app.DisposeAsync();
```

* 整段在线程池，UI 线程不参与等待。
* 超时 5s 逾期吞掉，不阻塞 UI。
* `_runningApp` / `_runningTask` 字段**先置 null 再异步收尾**，避免重入时拿到旧实例。

### 5.3 退出路径

* **菜单「退出」**：先 `notifyIcon.Visible = false`（用户立即感知）→ 异步 `StopWebAppAsync()` → `ExitThread()`。
* **`Dispose(bool disposing)` 兜底**（用户从任务管理器/关机触发的进程退出）：
  1. 置 `isDisposed = true`，挡后续 UI 更新。
  2. 反订阅 `SystemEvents.UserPreferenceChanged`。
  3. 同步 `StopWebAppAsync().GetAwaiter().GetResult()`（此时无消息循环，无死锁）。
  4. `notifyIcon.Visible = false; notifyIcon.Dispose();`
  5. Dispose 7 个缓存 Icon。

### 5.4 Dispose 竞态守卫

* `volatile bool isDisposed` 字段，`UpdateMenuState()` / `UpdateIcon()` 入口判直接返回。
* 设置 `notifyIcon.Icon = ...` 用 `try/catch (NullReferenceException) / (ObjectDisposedException)` 包住：`NotifyIcon` 在 Dispose 与 UpdateIcon 之间有窄竞争窗口（内部 `_window` 被置空后 UpdateIcon 会 NRE）。

## 六、菜单操作行为

### 6.1 启停切换

* 按下立即禁用「启停」项防重入。
* 启动前重读端口（用户可能在 WebUI 设置页改过 `Web:Port`，Tray 内存里是缓存）。
* 成功气泡：`PersonalMediaManager 已启动：<访问地址>`（约 2.5s）；`<访问地址>` 取局域网 IPv4 优先（`LocalNetwork.BuildShareUrl`），探测不到回退 `http://localhost:<port>`。
* `finally` 恢复菜单状态并 `UpdateMenuState()`。

### 6.2 打开 WebUI / 复制访问地址

* **未运行时禁用菜单项**（避免点了浏览器空白）。
* **地址区分（重要）**：
  * 「打开 WebUI」是本机自己开 → 用 `http://localhost:<port>`（不依赖网卡探测、不受 IP 变化影响，最稳）。
  * 「复制访问地址」是发给手机 / 平板 / 另一台电脑用 → 复制**局域网 IPv4** 地址（`LocalNetwork.BuildShareUrl`：枚举网卡取私有网段首选，排除环回 / 虚拟网卡 / APIPA），探测不到时回退 `http://localhost:<port>`。
* 启浏览器：`Process.Start(new ProcessStartInfo(url) { UseShellExecute = true })`，异常弹 `MessageBox`。
  > **已落地**：`PmmTrayContext.OpenUrl` 统一 `UseShellExecute = true` 直连启动（无 cmd 黑窗）；提权运行时经 explorer.exe 转交的兜底见 §7.1。
* 复制：`System.Windows.Forms.Clipboard.SetText(url)`，气泡「已复制访问地址」回显完整地址（让用户确认拿到的是可分享的局域网地址）。

### 6.3 配置端口 Dialog

极简 Modal：

* `NumericUpDown`（1–65535）+ 确定/取消。
* 字体显式 `new Font("Microsoft YaHei UI", 9F)`、`AutoScaleMode = Font`、`TableLayoutPanel + AutoSize`、`FormBorderStyle = FixedDialog`、`ShowInTaskbar = false`、`StartPosition = CenterScreen`。

流程：`LocalConfigStore.TryValidatePort` → `SetOverridePort` → 停旧 Kestrel → 起新 Kestrel → 气泡告知新地址。期间禁用「配置端口」与「启停」项。

### 6.4 配置数据库位置 Dialog

* `SaveFileDialog`：`Filter = "SQLite (*.db)|*.db|所有文件|*.*"`、`OverwritePrompt = false`（允许选已有文件，目的是切到现有 db）、初始位置预填当前 db 所在目录。
* 校验通过 → `SetOverrideDbPath` → 停 → 起。

**重要边界（用户感知）**：
* 切到**已有 PMM db** = 切换数据集（典型：备份恢复、多账户切换）。
* 切到**空路径 / 非 PMM db** = EF Migration 会自动建 schema，但无业务数据 → `SetupGuard` 把所有业务请求拦回初始化向导。**用户重启后看到的是初始化页**，不是空仪表盘 —— 这是正确行为，但 Dialog 上需明文提示：「切到不存在的路径将创建空数据库并触发初始化向导」。

### 6.5 开机自启切换

菜单 `Checked` 来自缓存状态 `_autoStartEnabled`（`WindowsAutoStart.IsEnabled()` 读 HKCU\Run 值；为兼容升级用户也查残留旧计划任务，故构造期异步读一次回填、点击切换后更新）。点击：

* 已勾选 → `Disable()`（删 Run 值 + 顺带删残留旧任务）→ 取消勾选 → 气泡「已取消开机自启」。
* 未勾选 → `Enable()`（写 HKCU\Run 值）→ 勾选 → 气泡「已设置开机自启（下次登录生效）」。
* HKCU\Run 是当前用户配置单元，普通权限即可读写，正常不会失败；偶发异常弹 `MessageBox`（不静默），状态不变。

### 6.6 启动气泡

* **手动启动**：完成后弹 4s 气泡，含访问地址（局域网 IPv4 优先，探测不到回退 localhost；见 §6.2）。
* **`--autostart` 自启**：完全不弹（开机时桌面不要被打扰）。

## 七、执行级别与开机自启注册

### 7.1 执行级别 = asInvoker（普通权限，**不提权**）

全配置经 `app.manifest`（`requestedExecutionLevel level="asInvoker"`）声明**以普通权限、跟随启动者令牌运行**。

* **为何不提权**：`requireAdministrator` 会让进程跑在 UAC「完整令牌」的独立登录会话（LUID），**看不到普通会话映射的网络盘**（`Y:` / `Z:` 等）——归档到网络盘时 `Directory.CreateDirectory` 抛 `DirectoryNotFoundException`。「归档目标盘可达」优先级高于「数据贴 exe」便携性，故摘除提权（推翻 v0.4 决策）。
* **数据落点**：普通权限下，exe 目录可写则数据贴 exe（便携）；装在 `Program Files\` 等只读位置时 `AppPaths` 写探针失败 → 自动回退 `%LocalAppData%\PersonalMediaManager`（标准 Windows 应用模型：程序文件只读 + 用户数据可写）。安装那一刻往 `Program Files` 写文件的提权，由安装器 / Explorer 复制一次性承担，**运行时不需要**。
* **全配置一致**：`csproj` 无条件引用 `<ApplicationManifest>`（单 TFM `net10.0-windows` 下无需 TFM 条件，Debug + Release 都引用）；asInvoker 本就是默认级别，行为统一。
* **打开浏览器**：`PmmTrayContext.OpenUrl` 仍检测 `IsProcessElevated()`——正常 asInvoker 下恒 false 走直连 ShellExecute；仅当用户手动「以管理员身份运行」时才经 `explorer.exe` 转交（避免浏览器继承管理员令牌）。该兜底保留。

### 7.2 开机自启 = HKCU\Run（普通权限登录即启）

摘除提权后，自启回退到 `HKCU\...\Run` 值：asInvoker 程序经 Run 项在登录时即以普通完整性级别静默启动、不弹 UAC、跑在交互会话（有托盘 UI），与「普通权限 → 共享会话网络盘映射」目标一致。

* **实现**：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值 `PersonalMediaManager` = `"{exe}" --autostart`；零 shell-out。
* **`Enable()`**：`Registry.CurrentUser` 写 Run 值（`WindowsAutoStart.BuildRunCommand` 构造，引号包裹 exe 容纳含空格安装目录）+ 顺带删残留旧计划任务。
* **`Disable()`**：删 Run 值（不存在静默吞）+ 删残留旧任务。
* **`IsEnabled()`**：Run 值存在 **或** 残留旧计划任务存在均视为已启用（兼容升级用户菜单显示）。
* **升级迁移** `MigrateLegacyIfNeeded()`：启动时把「残留旧『最高权限计划任务』」的升级用户一次性转回普通权限 Run 值（删任务 + 写 Run，避免旧任务继续提权自启把网络盘隔离回去）；托盘构造期在线程池调用（不阻塞 UI，失败不中断启动）。删旧「最高权限」任务需管理员：被旧任务（提权）拉起的那次普通权限删即成功、不弹 UAC；仅「非提权手动启动且旧任务尚在」才自提权（`runas`）删一次。用户拒绝则旧任务残留，下次被它拉起时清理，自启不丢（Run 值已写好）。
* exe 路径：`Environment.ProcessPath`（单文件发布指向真实 exe，非临时解压目录）；`dotnet run` 拿到 `dotnet.exe`，该功能本就无意义，允许失真。

> **现状**：`WindowsAutoStart.cs` 已落地 HKCU\Run 实现（含旧计划任务反向迁移）；v0.4 的「最高权限计划任务」方案已废弃。单实例 Mutex 同步由 `Global\` 改 `Local\`（普通令牌无 `SeCreateGlobalPrivilege`，`Global\` 会抛 `UnauthorizedAccessException`）。

## 八、单文件发布约束

`PersonalMediaManager.Launcher.csproj` 关键属性（节选，单 TFM `net10.0-windows`）：

```xml
<PropertyGroup>
  <TargetFramework>net10.0-windows</TargetFramework>
  <DebugType>embedded</DebugType>
  <RuntimeIdentifiers>win-x64</RuntimeIdentifiers>
</PropertyGroup>
<PropertyGroup Condition=" '$(RuntimeIdentifier)' != '' ">
  <SelfContained>true</SelfContained>
  <PublishSingleFile>true</PublishSingleFile>
  <IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
</PropertyGroup>
```

**关键决策**：

* **不启用** `<EnableCompressionInSingleFile>` —— 压缩拖慢首启 1–2 秒。PMM 常驻进程，产物体积不敏感（多个十几 MB 可接受），启动延迟更敏感（用户感知强）。
* **wwwroot + appsettings.json 嵌入 Host 程序集**（`GenerateEmbeddedFilesManifest` + execution 阶段动态 `EmbeddedResource`，锚点 `_CalculateEmbeddedFilesManifestInputs`）：Vite build 产物与出厂 appsettings 编译进 `Host.dll` 随单文件 exe 内置，运行时 `ManifestEmbeddedFileProvider` 内存直读 → **发布产物收敛为单一 exe**（不再外置 `wwwroot/` 与 `appsettings.json`）。`IncludeAllContentForSelfExtract` 维持 false（仅约束散文件 content，与嵌入资源无关）。前端开发热更新走 vite dev(5173)，与发布产物解耦。
* RID 用复数 `<RuntimeIdentifiers>`（避免 `<RuntimeIdentifier>` 单数污染 Debug 输出路径并触发 `NETSDK1047`）。
* `SelfContained=true` 必须**全解决方案统一**（已由 `Directory.Build.props` 处理），否则触发 `NETSDK1150`。
* **manifest 全配置引用**：`<ApplicationManifest>app.manifest</ApplicationManifest>` 无条件引用（单 TFM 下无需 TFM 条件；Debug + Release 一致，§7.1）；执行级别 `asInvoker`（普通权限），发布单文件 exe 内嵌该 manifest（apphost 资源）。

发布命令：`dotnet publish src\PersonalMediaManager.Launcher -c Release -r win-x64`（由 `scripts/build-win.ps1` 调用）。

首次运行解压到 `%TEMP%\.net\PersonalMediaManager\<hash>\`（仅 runtime/native，只读），后续启动复用；db / logs / keys / local.json 落「程序目录\data\」（不可写回退 `%LocalAppData%\PersonalMediaManager\`）。**asInvoker 普通权限运行（§7.1）下**：装在可写目录则数据贴 exe（便携）；装在 `Program Files\` 等只读位置时写探针失败、自动回退 `%LocalAppData%`（此即标准模型，非异常路径）。摘除提权时，`AppPaths` 还会把旧版提权安装「贴 Program Files\exe」的 `data\` 整目录一次性迁回新根（含 keys / pmm.db-wal/-shm，规避加密字段解不开与 WAL 孤儿损坏；留 `.migrated-from.txt` 面包屑）。

## 十一、macOS 支持移除

macOS 支持已移除（2026-06-11 决策）：本产品仅支持 Windows，原 macOS 方案（NSStatusItem 托盘 / LaunchAgent 自启 / PidFile 单实例 / 全盘访问引导）不再实施，历史方案见 git 历史。

`IPlatformTray` / `IPlatformAutoStart` / `IPlatformSingleInstance` 三个平台抽象接口保留——保留理由不再是跨平台回填，而是隔离 OS API、便于单元测试替身。
