## 〇、总则

### 0.1 自动化开发交付契约

每条「**子任务**」必须满足全部以下条件方可标记完成（DoD, Definition of Done）：

| # | 项 | 度量方法 |
|---|---|---|
| 1 | 代码已写入正确项目目录，命名空间与 `CLAUDE.md` §七 一致 | 文件路径 + 顶部 `namespace` 检查 |
| 2 | 该子任务关联的测试已新增 / 更新且通过 | `dotnet test --filter` 命中 |
| 3 | `dotnet build` 全解决方案 0 error、0 warning（warning 等级 `TreatWarningsAsErrors=true`） | CI / 本地 build |
| 4 | 不破坏「累积回归集」 | 见 §0.4 |
| 5 | 提交信息中文、说明 WHY 而非 WHAT | `git log --format=%s` 抽样 |

### 0.2 分支与提交约定

- 每个**阶段**开一个 `feature/<阶段编号>-<简述>` 分支；每个**子任务**一个 commit。
- 阶段验收通过 → 合并回 `main` → 删分支。
- `git worktree` 已放开（`CLAUDE.md` §八原「禁用」红线已解除）；注意 VS 同一时刻只跟踪主工作树，手动开 worktree 时自行留意当前在哪棵树 / 哪个分支。
- commit 信息模板：
  ```
  <子任务编号> <动词> <对象>：<一句话 why>
  例：B4.2 实现 JwtTokenService：支持 7 天内自动续签，避免前端频繁登录
  ```

### 0.3 测试金字塔（强制比例）

> 现行测试矩阵为 **6 个测试项目**（与 `CLAUDE.md` §十二 一致）：下表前 4 项为定稿时主矩阵及占比目标；`Infrastructure.External.Tests` / `Launcher.Tests` 系后续转正成员，未单列占比。

| 层 | 项目 | 占比目标 | 关注点 |
|---|---|---|---|
| 单元 | `Domain.Tests` | 40% | 聚合行为、状态机转移、不变式守护 |
| 单元 | `Application.Tests` | 30% | 应用服务用 Mock 契约 + In-Memory 仓储，覆盖业务分支 |
| 集成 | `Infrastructure.Persistence.Tests` | 20% | EF Migration + SQLite in-memory + 拦截器 + 索引生效 |
| 集成 | `Host.Tests` | 10% | `WebApplicationFactory` + 真实 DbContext 跑 API + SignalR |
| 集成 | `Infrastructure.External.Tests` | —（转正成员） | TMDB 客户端 / AI 协议与解析 / 升级链 / Webhook 出站发送器（HTTP 桩 + 主备切换） |
| 单元 | `Launcher.Tests` | —（转正成员） | `LocalConfigStore` 读写 / JSON 损坏自愈 / 端口与连接串覆盖校验等纯逻辑 |

> Platform（`FileMover` / `FileSystemWatcher` 适配 / DataProtection 包装）测试仍按需新建（涉及真实文件 IO），不计入主测试矩阵但纳入回归。

### 0.4 累积回归矩阵（**自动化必跑**）

> **CI 引擎 = 自建 Azure DevOps（Azure Pipelines YAML，self-hosted agent）**——详见 §0.7。
> 测试统一用 `dotnet test --logger trx --collect:"XPlat Code Coverage"`，结果走 `PublishTestResults@2` + `PublishCodeCoverageResults@2` 任务上传。

每完成一个**阶段**，CI 必须按下表跑「**该阶段所在行及以上所有行**」的回归集。任何一条失败 → 阶段不通过。

| 阶段 | 必跑回归集 |
|---|---|
| A | 解决方案 `dotnet build` + 全部 6 测试项目 `dotnet test`（定稿时为 4 个，External.Tests / Launcher.Tests 转正后为 6 个） |
| B | A 全集 + Auth 冒烟（login → /api/auth/me 200 → logout → /api/auth/me 1000）+ Setup 冒烟 |
| C | B 全集 + 各设置模块 GET/CRUD 端到端（`WebApplicationFactory`）+ 加密字段读写 |
| D | C 全集 + 端到端 E2E1（电影自动归档）+ E2E2（剧集多季归档）+ E2E3（无法识别→人工→bind-tmdb→归档）+ 状态机所有合法转移单测 |
| E | D 全集 + 启动器单实例检测 + 配置导入导出往返一致性 + 前端构建产物嵌入 wwwroot 后 `/` 返 200 |
| F | E 全集 + Windows 一次手工冒烟（清单见 §F.4；macOS 冒烟已取消，支持移除）|

### 0.5 通用代码红线（自动化必须自检）

> 这些是**编译/测试可能不报错但违反 `CLAUDE.md` §八的红线**。**自动化现状（2026-06-12 校准）**：仅「自动化状态」列标 ✅ 的条目有 CI 脚本守门（`check-refs.ps1` 查项目引用图；`check-redlines.ps1` **仅**查 Launcher UI 框架）；其余为**人工约定**，PR review 时按「检测方法」列自查：

| 红线 | 检测方法 | 自动化状态 |
|---|---|---|
| 同一 DbContext 实例 `Task.WhenAll` 并发查询 | `grep -nE "Task\.WhenAll\([^)]*_?(db|context|ctx)\." src/` 必须为空 | 仅人工约定 |
| `Domain` 引用任何外部包 | `Domain.csproj` 必须无 `<PackageReference>`、无 `<ProjectReference>` | 部分 ✅（`ProjectReference` 由 `check-refs.ps1` 守门；`PackageReference` 仅人工） |
| `Application` 引 EF Core / ASP.NET Core / Quartz / HttpClient | `Application.csproj` 包白名单：仅 `Microsoft.Extensions.*` | 仅人工约定（`check-refs.ps1` 只查 `ProjectReference`，不查 NuGet 包） |
| 三个 Infrastructure 子项目互引 | 项目引用图脚本校验 | ✅ `check-refs.ps1` |
| Host 直接引 Domain | `Host.csproj` 不得出现 `ProjectReference Include="...Domain.csproj"` | ✅ `check-refs.ps1` |
| Controller 出现 `[HttpPut]` / `[HttpDelete]` / `[HttpPatch]` | `grep -rn "HttpPut\|HttpDelete\|HttpPatch" src/PersonalMediaManager.Host/Controllers` 必须为空 | 仅人工约定 |
| 缩写大写：`TMDB / AI / API / URL / JSON / HTTP` 出现在类型 / 成员名 | 自定义 Roslyn 分析器或 `grep` | 仅人工约定 |
| Launcher 引入跨平台 UI 框架（Eto / Avalonia / WindowsAppSDK / MAUI） | `grep -rnE "Eto\.Forms\|Avalonia\|Microsoft\.WindowsAppSDK\|Microsoft\.Maui" src/PersonalMediaManager.Launcher/` 必须为空 | ✅ `check-redlines.ps1`（csproj `PackageReference` + cs `using` 双路扫描） |
| Launcher 引入 `H.NotifyIcon` 任何变体（NuGet 上无 WinForms 变体，走 SDK 内置 `System.Windows.Forms.NotifyIcon`） | `grep -rn "H\.NotifyIcon" src/PersonalMediaManager.Launcher/` 必须为空 | 仅人工约定（`check-redlines.ps1` 禁包清单暂未含 `H.NotifyIcon`） |
| `.github/workflows/` 下出现 `pr-ci.yml` / `release.yml` 之外的 workflow；或出现 GitLab CI / Jenkins / CircleCI / Travis 配置 | `ls .github/workflows` 仅允许 `pr-ci.yml`（公开 PR 门禁）与 `release.yml`（发版 + main 开发构建）；其它第三方 CI 配置必须不存在 | 仅人工约定 |
| 出现 `dev.azure.com` 路径（云端 Services 标识，本项目用 Server SKU） | `grep -rn "dev\.azure\.com" .` 必须为空（docs/CLAUDE.md 中提到的「禁止」字样除外，脚本用 `--invert-match "禁止\|不要"` 排除） | 仅人工约定 |

> 原「`git worktree add` 出现在任何脚本」红线已随 `CLAUDE.md` §八 worktree 禁令解除而删除（2026-06-12 校准）。

**A. Windows agent 注册步骤（在 Windows 机器上跑）**

1. Server Web UI → Project Settings → Agent pools → 选 `Default` pool（或新建 `pmm` pool）→ `New agent` → 下载 `vsts-agent-win-x64-*.zip`。
2. 解压到 `C:\azagent\pmm-win\`。
3. PowerShell（管理员）：
   ```powershell
   cd C:\azagent\pmm-win
   .\config.cmd `
     --unattended `
     --url http://<azure-server>/<collection> `
     --auth pat `
     --token <PAT> `
     --pool Default `
     --agent pmm-win `
     --runAsService `
     --windowsLogonAccount "NT AUTHORITY\NetworkService"
   ```
4. 验证：服务管理器看到 `vstsagent.<collection>.Default.pmm-win` 已运行（服务名格式 = `vstsagent.{Collection}.{Pool}.{Agent}`，Collection 实值见 `CLAUDE.local.md`，不入库）。
5. capabilities 验证：在 agent pool 页应看到 `pmm-win` 自动上报的 `Agent.OS = Windows_NT`、`DOTNET_HOST_PATH`、`PowerShell.Version`。

**B. macOS agent**：macOS 支持已移除（2026-06-11 决策），本节原 macOS agent（Mac mini）配置清单与注册待办整段作废。

**C. agent pool 与 demands 在 yaml 中的引用**

在 `azure-pipelines.yml` 的 job 上声明 demands 选 agent（现行管道按 agent 名精确锁定，非 `Agent.OS`）：
```yaml
jobs:
  - job: WindowsAgent
    pool:
      name: Default
      demands:
        - Agent.Name -equals pmm-win
    steps: [...]
```

**D. PAT 生命周期管理**

- agent 注册用的 PAT 默认有效期 90 天，到期 agent 会自动掉线。
- 建议生成时**勾长有效期 + 仅 Agent Pools (read & manage) 权限**，到期前 1 周用同样命令带新 PAT 重跑 `config.cmd` 即可。

## 八、关键风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| AI 提供商成本失控 | 高 | 硬上限 2 次 + 自动禁用机制（D.3）+ `Audit_AiCall` 看板 |
| TMDB 429 | 中 | Polly 节流 40 req/s + Retry-After + 元数据 24h 缓存 |
| 文件系统并发（一个文件同时被监控 + 全量扫描发现） | 中 | `Media_Item(SourcePath) UQ` 索引（A4.6）+ 入库 `INSERT OR IGNORE` |

| EF Migration 在用户已有 DB 上失败 | 低（开发阶段无兼容压力） | 启动时 `db.Database.Migrate()` 失败 → 重命名旧 db 为 `.bad-<ts>` → 重建新 db |
