# 需求规范 — 初始化引导向导

> 关联：`需求规范-启动方式与托盘常驻.md`、`Setup.vue`、`SetupController` / `SetupService` / `SetupGuardMiddleware`。

## 1. 背景与缺口

旧 `/setup` 向导只做一件事：创建管理员账号 + 写 `System.SetupCompleted=true` 标记，随即跳仪表盘。但要让系统真正跑通「监控 → 解析 → 刮削 → 归档」这条链，还有 3 个必需配置散落在 3 个互不相干的设置子页，新手装完没有任何线索知道要去找：

| 必需项 | 旧位置 | 缺失后果 | 隐蔽度 |
|---|---|---|---|
| 管理员账号 | `/setup`（已有） | 进不去 | — |
| 至少 1 个监控目录 | 设置-监控目录 | 无文件被发现，手动扫描报错 | 中 |
| TMDB v4 Token | 设置-TMDB | 刮削抛异常 → 文件全 Failed | 中 |
| 把 3 个内置分类的落点 `<UNSET>` 改成真实目录 | 设置-媒体分类 | **解析全绿、归档集体 Failed** | **极高（隐形雷）** |

> 分类有种子（电影/电视剧/动漫 + 匹配规则均已就绪），用户易误以为分类已配好，但落点全是 `<UNSET>` 占位符，排查成本极高。本向导把这条隐形雷显式化为强引导的一步。

## 2. 设计目标

把「跑通系统所需的必需 + 推荐配置」串成一条线，首次启动一次配齐；同时不强制——允许逐项「暂时跳过」，完成后由 Dashboard「配置完成度」卡片持续提醒未配齐项（业界 Plex/Jellyfin/Emby 惯例）。

## 3. 向导流程（6 步）

```
欢迎 → ① 账号 → ② TMDB → ③ 监控目录 → ④ 归档设置 → ⑤ AI(可选) → 完成
       必经/建完即登录   可跳过/测连接    可跳过/测连通    可跳过/统一根目录填充   可选/厂商预设   就绪度汇总
```

| 步 | 名称 | 可跳过 | 内容 | 调用端点 |
|---|---|---|---|---|
| 0 | 欢迎 | — | 说明将配置哪些、预计 3–5 分钟 | — |
| 1 | 管理员账号 | ✗ 必经 | 用户名/密码/确认 → 建完**立即自动登录** | `POST /setup/admin` + `/auth/login` |
| 2 | TMDB | ✓ | v4 Token（`eyJ` 格式校验）+ 优先/回退语言；**测试连接**；失败时内联**代理补救** | `settings/tmdb/update` `/test`、`settings/general/update`(Proxy_*) |
| 3 | 监控目录 | ✓ | 加 ≥1 条（路径/别名/网络盘）；逐条**测连通** | `settings/watch/folders` `/{id}/test` |
| 4 | 归档设置 | ✓(重点引导) | **统一根目录一键填充** 3 个分类落点 + 微调（残留 `<UNSET>` 标红）；**文件操作方式**(移动/复制/硬链接)；**同名冲突策略** | `settings/categories/update`、`settings/general/update`(File.Operation / Archive_ConflictPolicy) |
| 5 | AI 提供商 | ✓(可选) | 标注「可选，不配则非标准命名进人工队列」；复用 10 厂商预设 + ApiKey + **测试** | `settings/ai-providers` `/test` |
| 6 | 完成 | — | 拉 `checklist` 汇总各项 ✅/⚠；置完成标记 → 进 Dashboard | `GET /setup/checklist` + `POST /setup/complete` |

### 关键交互
- **统一根目录填充**（第 4 步）：填一个媒体库根（如 `D:\Media`），自动给 3 个分类拼 `D:\Media\电影`、`D:\Media\动漫`… 再允许逐个微调。一次解决 3 个落点。
- **文件操作方式**（第 4 步）：默认 Move 会移走源文件，PT/BT 做种用户应选「硬链接」。三种模式后果在界面内说明。
- **代理补救**（第 2 步）：TMDB 测试失败时内联弹出「连接失败？可能需要代理」+ 启用开关 + 地址，配完重测；不打扰不需要代理的用户。
- 每个可跳过步的「暂时跳过」直接前进、不写任何配置。

## 4. 配置就绪度与兜底

- **新增端点** `GET /api/setup/checklist` → `SetupChecklistResponse`：
  `{ isCompleted, hasAdmin, watchFolderCount, tmdbHasApiKey, categoryTotalCount, categoryUnsetCount, aiProviderCount }`。
  其中 `categoryUnsetCount` = `TargetRoot == "<UNSET>"` 的分类数（与 `DataSeeder.UnsetRoot` 一致）。
- **Dashboard 完成度卡片**：拉 `checklist`，若 `!tmdbHasApiKey || watchFolderCount==0 || categoryUnsetCount>0`，在仪表盘顶部显示提醒条 + 一键跳对应设置页；配齐后自动消失。

## 5. 后端机制

### 5.1 复用现有设置端点
向导第 ②~⑤ 步不新增写逻辑，全部复用现有 `settings/*` 端点（含各自 `/test`）。第 ① 步建账号后**立即登录拿 JWT**，后续步骤带 token 调用。

### 5.2 SetupGuardMiddleware 调整
旧逻辑：`SetupCompleted=true` 前拦截除白名单外所有 API。为让向导「建账号 → 登录 → 调设置端点 → 最后才 complete」成立，做两处调整：
1. **白名单新增** `/api/setup/checklist`（向导续配 + Dashboard 卡片，仅计数/布尔无密钥明文）与 `/api/auth/login`（向导登录拿 JWT）。
2. **未完成时放行「已认证 Admin」**：能登录成 Admin 者本就拥有全部设置权限（无安全回归），且 `complete` 前唯一可登录者即刚建的那个 Admin。
3. 中间件**移到 `UseAuthentication` 之后、`UseAuthorization` 之前**：需读已认证身份；又须在授权前拦截，使未 setup 的匿名请求返 1000「请先完成初始化」而非被 FallbackPolicy(Admin) 401/403。

### 5.3 安全性
- 未完成 setup 且非 Admin 的匿名请求，依旧只能碰白名单（status/checklist/login/health/diag 及 setup/admin、setup/complete）。
- 建账号端点保留 `hasAdmin` 纵深守门，防匿名建第二个管理员。
- 完成后 guard 全放行（静态缓存），恢复正常 Authorization 流程。

## 6. 断点续配

`complete` 在最后一步才置位，中途退出再进仍回 `/setup`。向导 `onMounted` 拉 `status`：
- `hasAdmin && 已登录`（token 持久化）→ 跳过账号步，从第 ② 步起、拉 `checklist` 续配。
- `hasAdmin && 未登录` → 账号步切「登录以继续配置」态（而非重复建账号）。
- 全新 → 欢迎页 + 账号步。

## 7. 不纳入向导的设置（有合理默认，留设置页）

归档命名模板、字幕、Webhook、软件更新、备份、音频探测/ffmpeg、端口/各类阈值/日志级别/扫描周期等——均有种子默认值或属可选功能，开箱即用。完成页提示「更多设置进入系统后在『设置』里调整」。
